# Neo4j Integration: API vs Model Extension Explained

## "Exposes this metadata via API for the Ontos product detail view"

When someone clicks on a Neo4j data product in Ontos, the product detail page calls `/api/neo4j/summary` to show live graph info (node counts, relationship types, freshness).

The API exists so the frontend has somewhere to fetch that data from. Without it, Ontos has no way to display anything about what's inside a Neo4j database.

---

## "Extends the ODPS model to represent graph-specific output ports"

We added fields (`bolt_url`, `neo4j_database`, `neo4j_labels`, `neo4j_relationships`) to the Server model in `data_products.py`.

Before this change, an output port in Ontos could only describe Databricks tables, Snowflake, Kafka, S3, etc. Now it can also describe a Neo4j graph — what connection to use, what node labels exist, what relationships exist.

It's extending the data model so Ontos "knows" what a Neo4j output port looks like.

---

## In Short

| Concept | Purpose |
|---------|---------|
| **API** | How the frontend gets live data from Neo4j |
| **Model extension** | How Ontos stores/represents that a data product outputs to Neo4j (not just Databricks) |

---

## Does the API Generate the ODPS YAML?

**No.** The API (`/api/neo4j/summary`) returns raw JSON — the live graph metadata. It doesn't generate or create the ODPS YAML file.

The ODPS YAML was generated by a script we ran locally that:

1. Called the handler to get live data from Neo4j
2. Formatted it as YAML
3. Wrote it to a file

To have the API generate the ODPS YAML, we'd need to add a new endpoint like `/api/neo4j/generate-odps` that returns a YAML file. That doesn't exist yet.

---

## What Exists Now (for demo)

| What | Does it exist? | Where |
|------|---------------|-------|
| `/api/neo4j/summary` → returns JSON | Yes | In the deployed app |
| Script that generates ODPS YAML from live Neo4j | Yes | We ran it locally (one-time) |
| API endpoint that generates/returns ODPS YAML | No | Would need to be built |

## Demo Notes

The data product is already registered in Ontos (product detail page).

The right sidebar (Contacts, Lifecycle, Certification, Publication, Overall Data Quality) is where the live Neo4j graph metadata will appear — node counts, relationship types, data freshness. The API (`/api/neo4j/summary`) already exists and returns that data. The next step is wiring a widget there that calls it and displays it alongside the existing panels.

**Demo flow:**
1. Show the product detail page → "here's the Neo4j graph registered as a data product in our catalog"
